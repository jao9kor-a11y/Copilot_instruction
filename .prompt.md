# CAPL Compiler Warning Prevention Rules

Before generating any CAPL `.can` file, ensure the code is free from common Vector CAPL compiler warnings.

## write() Formatting Rules

Always verify every `write()` and `writeEx()` format specifier matches the variable data type.

**Critical Rules:**

* **Never use `%c` format specifier** - causes "format specifier may cause undefined behaviour with multibyte file encodings"
* Avoid character printing with `%c` entirely

**Use instead:**

* `%d` for signed integers (int, char as integer)
* `%u` for unsigned integers
* `%X` or `%02X` for hexadecimal values
* `%ld` for long integers
* `%f` or `%.2f` for floating-point values
* `%s` for strings

**Examples:**

Incorrect:
```capl
char gStatus = 'A';
write("Status = %c", gStatus);  // WARNING: undefined behaviour
```

Correct:
```capl
char gStatus = 'A';
write("Status = %d", gStatus);  // Print as integer (65)
write("Status = 0x%02X", gStatus);  // Print as hex (0x41)
```

For character display, use integer representation or convert to string.

Always test format specifiers match argument types to prevent compiler warnings.

# CAPL Error Analysis and Debugging

When asked to analyze and fix compilation errors in CAPL files, follow this systematic approach:
## 1. Duplicate Function Detection

**Critical:** CAPL does not support function overloading. Each function must appear exactly once.

**Steps:**
* Search entire file for duplicate function implementations
* Search for duplicate function prototypes
* Keep only ONE implementation per function
* Keep only ONE prototype per function (if needed)
* Remove all duplicates completely

**Common patterns:**
```capl
// WRONG: Duplicate function
void MyFunction() { }
void MyFunction() { }  // ERROR: duplicate

// CORRECT: Single implementation
void MyFunction() { }
```

## 2. Function Prototype Validation

**Rule:** Prototypes must EXACTLY match implementations.

**Verify for every function:**
* Return type identical
* Function name identical (case-sensitive)
* Parameter count identical
* Parameter types identical
* Parameter order identical

**Common errors:**
```capl
// WRONG: Mismatched prototype
void ProcessData(int value);
void ProcessData(byte value) { }  // ERROR: int vs byte

// CORRECT: Matching prototype
void ProcessData(int value);
void ProcessData(int value) { }
```

**Best practice:** Only add prototypes when required by CAPL (forward references). Otherwise omit them.

## 3. Invalid C/C++ Syntax Removal

**CAPL is NOT C/C++.** Never use:

**Forbidden constructs:**
* `char[]` return type
* `char*` pointers
* `string` type
* Any pointer syntax (`*`, `&`, `->`)
* `struct` definitions
* `typedef`
* `class`
* `malloc` / `free`
* C++ templates
* C++ namespaces

**Correct CAPL string handling:**
```capl
// WRONG: C-style return
char[] GetName() { }

// CORRECT: CAPL approach
void GetName(char dest[]) 
{
  strcpy(dest, "Name");
}

// Or use write() directly
void PrintName() 
{
  write("Name");
}
```

## 4. String Function Correction

**Problem:** Functions cannot return `char[]` or `char*` in CAPL.

**Solutions:**

**Option A:** Use output parameter
```capl
void GetStateName(enum State s, char buffer[])
{
  switch(s)
  {
    case STATE_INIT: strcpy(buffer, "INIT"); break;
    case STATE_IDLE: strcpy(buffer, "IDLE"); break;
  }
}
```

**Option B:** Use direct write() without return
```capl
void PrintStateName(enum State s)
{
  switch(s)
  {
    case STATE_INIT: write("INIT"); break;
    case STATE_IDLE: write("IDLE"); break;
  }
}
```

**Option C:** Remove function, inline the logic
```capl
// Instead of calling GetStateName(), write inline:
switch(gCurrentState)
{
  case STATE_INIT: write("State: INIT"); break;
  case STATE_IDLE: write("State: IDLE"); break;
}
```

## 5. Variable and Timer Declaration

**Rules:**
* Declare ALL variables in `variables { }` section
* Declare ALL timers in `variables { }` section
* Each variable declared ONCE only
* Each timer declared ONCE only
* Never declare variables inside functions (except local scope)

**Common errors:**
```capl
// WRONG: Undeclared timer
on timer myTimer { }  // ERROR: myTimer not declared

// CORRECT: Declare first
variables
{
  msTimer myTimer;
}
on timer myTimer { }
```

**Check for:**
* Misspelled variable names
* Duplicate variable declarations
* Variables used before declaration
* Timers referenced but not declared

## 6. Enum Type Safety

**Rule:** Do not assign raw integers to enum variables.

**Common error:**
```capl
enum State { STATE_INIT = 0, STATE_IDLE = 1 };
enum State gState;

// WRONG
gState = 0;  // May cause warnings

// CORRECT
gState = STATE_INIT;
```

**Always:**
* Use defined enum constants
* Never use magic numbers
* Initialize enums with named constants

## 7. write() Format Specifier Audit

**Mandatory check:** Every `write()` and `writeEx()` call.

**Verification:**
* Count format specifiers (%, %d, %X, etc.)
* Count arguments after format string
* Verify each specifier matches argument type

**Format specifier reference:**
* `%d` - signed int, char (as integer)
* `%u` - unsigned int
* `%ld` - long
* `%lu` - unsigned long
* `%X` - hexadecimal (uppercase)
* `%x` - hexadecimal (lowercase)
* `%02X` - 2-digit hex with leading zero
* `%f` or `%.2f` - float/double
* `%s` - string (char array)

**Never use:**
* `%c` - causes encoding warnings
